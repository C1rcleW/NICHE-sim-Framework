# R0 研究决策记录

- 状态：**待决（OPEN）**
- 日期：2026-10-29
- 对应版本：0.1.2
- 决策范围：影响公式、家庭经济压力、收入归一化、易感性记录与研究解释
- 发布约束：**0.1.2 不修改上述模型行为**。本记录只冻结问题、证据与变更门槛。

## 1. 目的

0.1.2 是工程稳定性版本。复审确认：代码实现与研究文档之间存在若干研究语义差异，
不能作为普通工程修复顺手修改，否则会同时改变默认轨迹、基线、E1–E4 和敏感性结果。

R0 的作用是把这些差异变成可审计的决策项。任何一项在获得维护者确认前，都应视为
**待决**，而不是“已知 bug 已修复”或“研究结论已确认”。

## 2. 当前实现事实

### D1. 代际影响公式与归一化

当前代码 `family_abm/family/influence.py` 的实际计算为：

```text
received = strength × openness × share × (weighted_target − own_happiness)
weighted_target = Σ(w_i × capacity_i × health_i × happiness_i)
                  / Σ(w_i × capacity_i × health_i)
share = 1 / N_minors
```

公开文档曾写成：

```text
strength × openness × Σ(关系权重 × 养育能力 × 健康) × (加权平均来源幸福 − 自己幸福)
```

差异：

- 实际实现包含 `share = 1 / 未成年成员数`，公开公式遗漏；
- 实际实现把来源权重、养育能力和健康用于**加权平均**，没有把总和乘回影响量；
- 因此单一来源时，来源权重、养育能力、健康的正值会相互抵消；
- 多来源时，它们主要改变来源间的相对目标，而不是影响量级的绝对大小。

**待决问题**：代码归一化是研究意图，还是文档的乘积形式是研究意图？

### D2. 家庭经济压力与时间顺序

当前 `Household.step()` 先更新家庭总收入和 `economic_pressure`，再写入成员；
成员在 `step()` 中读取压力。由于环境默认把 Household 放在成员之前，首步成员收入尚为 0，
可出现首步压力为 1.0，下一步才与收入同步。不同注册顺序可能产生不同首步轨迹。

**待决问题**：

- 是否把经济压力改为步前预计算（与影响机制一致）；
- 首步是否作为 burn-in 丢弃；
- `income_baseline=0.25` 与默认人均收入量级是否匹配；
- `income_support` 是否应作用于成员收入，而不只是家庭总收入。

### D3. 生境经济维度与收入归一化

Web `/api/niche` 已输出 `raw_values`、`missing_dimensions`、`clipped_dimensions`；
未观测维度返回 `null`，不再由 Web 层伪造坐标。

当前经济位置的规则仍是：

```text
economic_position = clamp(raw_income, 0, 1)
```

没有定义 `income_ref`、收入基准或时间归一化。0.1.2 修复了坐标映射和缺失值展示，
但**没有选择归一化方案**。核心 `MicroNiche` 对从未更新的维度仍保留初始 0.5；
Web 不再把缺失维度当有效坐标输出，库调用方仍需自行区分“初始值”和“观测值”。

**待决问题**：收入归一化的理论含义、参考水平、是否随家庭/年龄/时间变化，
以及归一化后如何重跑实验与敏感性分析。

### D4. 易感性记录与 E2 成年期解释

`FamilyMember` 成年后不再接收影响，`apply_influence()` 在成年侧早退，
因此成员状态中的 `susceptibility` 可能停留在成年阈值前的值；它不一定等于当前年龄的
易感性函数值。E2 的“成年早期”结果需要区分“设计性零效应/边界帧效应”和真实阶段效力。

**待决问题**：

- `susceptibility` 状态是否对所有成员每步刷新，即使不接收影响；
- E2 成年早期结果是否应从阶段效力表中删除、单独标注，或重新定义统计窗口；
- 研究设计文档与结果 JSON 如何同步更新。

### D5. 复现与 reset 语义

- 智能体初始化会消耗随机流，正确用法是先建立 `Simulation(seed=...)`，再构造智能体；
- `Simulation.reset()` 当前不重置 Scheduler 时钟、不回滚智能体状态，只清空记录器。
  因此 reset 不是“重新开始同一条轨迹”；
- README 的旧示例应在 0.1.2 文档中改为正确的构造顺序。

**待决问题**：reset 是废弃、声明为只清记录，还是实现完整重跑语义。

### D6. 拟合模型边界

`resource_competition` 在默认 6 参数边界下，部分数据会停在失败哨兵，Web 返回
`model_not_applicable`。多状态拟合已显示每状态 R²/RMSE，但全局目标仍是未标准化 MSE/R²。
这些属于模型/方法边界，不应在 0.1.2 中静默调参。

## 3. 0.1.2 的决定

- 不修改 `influence.py`、`household.py`、`family_member.py` 的默认动力学；
- 不改变收入、压力、易感性的默认参数；
- 不重新固化 `baseline/default_seed42.json`；
- 不重跑并覆盖 E1–E4、敏感性、可约性结果；
- Web 仅修复可确认的工程缺陷：坐标映射、缺失值、运行隔离、输入契约、拟合展示。

## 4. 后续变更门槛

任何 R0 决策一旦确认并实施，必须一次性完成：

1. 更新本记录，写明选择、理由、影响范围和负责人；
2. 更新 README、研究设计 Markdown/DOCX、实验表格与发布说明；
3. 增加对应机制测试，先固定预期，再报告实测；
4. 重跑 `tools/baseline.py --out baseline/default_seed42.json` 并审查所有差异；
5. 重跑：
   ```bash
   python experiments/mechanism_validation.py --seeds 6 --steps 300 \
     --json experiments/results/mechanism_validation.json \
     --plot experiments/results/mechanism_validation.png
   python experiments/sensitivity_analysis.py --seeds 6 --steps 300 \
     --json experiments/results/sensitivity_analysis.json \
     --plot experiments/results/sensitivity_analysis.png
   python experiments/life_stage_reducibility.py --steps 240 \
     --json experiments/results/life_stage_reducibility.json \
     --plot experiments/results/life_stage_reducibility.png
   ```
6. 重新派生 `docs/experiments.md`、研究设计 DOCX/Markdown；
7. 运行完整测试（含 packaging 与浏览器）和文档一致性检查；
8. 作为独立版本/发布说明提交，不与普通 UI 或工程修复混合。
